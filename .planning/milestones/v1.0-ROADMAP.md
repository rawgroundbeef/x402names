# Milestone v1.0: Domain Registration Service

**Status:** SHIPPED 2026-02-05
**Phases:** 1-6
**Total Plans:** 13

## Overview

Build an agent-first domain registration API where agents pay USDC to register domains and point them at any URL. Six phases deliver the complete service: foundation infrastructure, external integrations, domain operations, registration flow with payment, URL forwarding, and production hardening.

### Phase 4: Registration Flow
**Goal**: Agents can register domains by paying USDC via x402
**Depends on**: Phase 3
**Requirements**: REG-01, REG-02, REG-03, REG-04, REG-05
**Success Criteria**:
  1. Agent can register an available domain by including x402 payment proof
  2. Registration is idempotent (same payment ID returns same result, no duplicate charges)
  3. Registration tracks state transitions (pending → paid → registered → live)
  4. Failed registrations after payment are automatically retried with backoff
  5. Successful registration stores domain, owner wallet, and target URL in database
**Plans**: 2 plans

Plans:

### Phase 5: URL Forwarding
**Goal**: Registered domains redirect visitors to target URLs
**Depends on**: Phase 4

  2. Redirect server handles multiple domains from database configuration
  3. DNS configuration documented for pointing domains at redirect server
  4. Domain owner can update target URL by paying small fee via x402
  5. URL update is idempotent and tracks state changes

## Milestone Summary

**Key Decisions:**
- Hono over Express (lightweight, modern, works everywhere)
- SQLite over Postgres (simple for v1, swappable via adapter)
- Abstract registrar interface (swap providers without rewriting business logic)
- Any-URL mapping not IPFS-only (broader utility)
- Custodial domain model (simplest v1, tracked by wallet)
- In-memory cache with 300s TTL for domain-to-URL mappings
- Separate redirect server on port 3001 (isolates public traffic)
- Flat $2.00 USDC fee for URL updates
- 100 req/min/IP sliding window rate limiting
- Aggregated validation errors for agent UX
- Static JSON error catalog with case-insensitive lookup

**Issues Resolved:**
- Railway config relative paths (fixed in deploy config)
- Bun.dns.resolve returning {address, ttl} objects (handled)
- URL/CNAME/FRAME records conflicting with A records (removed on DNS config)
- Combined API + redirect server on single port for Fly deployment

**Issues Deferred:**
- HARD-05: x402 payment signature server-side verification (facilitator handles settlement)
- ACME challenge / SSL provisioning for redirect server
- Per-wallet rate limiting (payment is natural throttle)

**Technical Debt:**
- createPaymentMiddleware factory exported but unused (routes use manual decoding)
- system table defined in schema but unused (reserved for future metadata)
- 4 human verification items flagged in Phase 6
