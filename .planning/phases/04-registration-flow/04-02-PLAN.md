       The x402 middleware handles payment verification, but the route handler needs the payer wallet for ownership tracking. The payment header contains the payment payload.

       ```typescript
       import { decodePaymentSignatureHeader } from '@x402/core/http';

       // Get payment header (x402 uses 'payment-signature' or 'x-payment')
       const paymentHeader = c.req.header('payment-signature') || c.req.header('x-payment');

       if (!paymentHeader) {
         // This shouldn't happen if middleware ran, but guard anyway
         return createProblemResponse(c, 402, 'error:payment_required', 'Payment Required', 'No payment header found');
       }

       // Decode to get PaymentPayload
       const paymentPayload = decodePaymentSignatureHeader(paymentHeader);

       // Extract payer from EVM exact scheme payload
       // The payload contains { authorization: { from: "0x..." }, signature: "0x..." }
       const payerWallet = (paymentPayload.payload as any)?.authorization?.from;

       if (!payerWallet) {
         return createProblemResponse(c, 400, 'error:invalid_payment', 'Invalid Payment', 'Could not extract payer wallet from payment');
       }
       ```

       Generate a payment ID from the payment header for idempotency:
       ```typescript
       // Use a hash of the payment header as payment ID for idempotency
       const paymentId = await generatePaymentId(paymentHeader);
       ```

       Create a helper function `generatePaymentId` that creates a SHA-256 hash of the payment header string (use `crypto.subtle.digest` or `Bun.hash`):
       ```typescript
       async function generatePaymentId(paymentHeader: string): Promise<string> {
         const hash = new Bun.CryptoHasher('sha256');
         hash.update(paymentHeader);
         return hash.digest('hex');
       }
       ```

    - The x402 middleware intercepts the request BEFORE the route handler
    - If no valid payment, middleware returns 402 (route handler never runs)

    - Settlement happens AFTER the route handler returns
    - The route handler must return a successful response (2xx) for settlement to proceed
    - The payer wallet is NOT available via Hono context - extract from payment header

Then in the route handler, validate the actual domain price against what was paid. If underpaid, return an error.

    1. Parse the payment header manually in the route handler

    4. The settlement will happen via the middleware if we use it, or we skip settlement for v1 (payment verification is sufficient, settlement is handled by the facilitator)

This gives us full control over dynamic pricing and access to the payer wallet. The payment header contains a cryptographically signed payment proof - the middleware's verification just checks this proof against a facilitator. For v1, we trust the payment header's signature (it was signed by the agent's wallet). In production, we would verify against the facilitator - but that's a Phase 6 hardening concern.

    Factory function:
    ```typescript
    export function createStatusRoutes(db: BunSQLiteDatabase<any>) {
      const router = new Hono();

      router.get('/:jobId/status', (c) => {
        const jobId = c.req.param('jobId');

        const job = db
          .select()
          .from(registrationJobs)
          .where(eq(registrationJobs.id, jobId))
          .get();

        if (!job) {
          return createProblemResponse(c, 404, 'error:job_not_found', 'Job Not Found', `Registration job ${jobId} not found`);
        }

        switch (job.state) {
          case 'processing':
            return c.json({
              state: 'processing',
              progress: job.progress,
              currentStep: job.currentStep,
              retryAfterSeconds: 2,
            });

          case 'succeeded':
            return c.json({
              state: 'succeeded',
              artifactUrl: `/domains/${job.domainName}/status`,
              domain: job.domainName,
              ownerWallet: job.ownerWallet,
              response: `Domain ${job.domainName} registered successfully`,
            });

          case 'failed':
            return c.json({
              state: 'failed',
              error: job.error || 'Registration failed',
              code: job.errorCode || 'unknown_error',
              domain: job.domainName,
            });

          default:
            return createProblemResponse(c, 500, 'error:invalid_state', 'Invalid Job State', `Job has invalid state: ${job.state}`);
        }
      });

      return router;
    }
    ```
