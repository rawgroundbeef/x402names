    1. Create root `package.json`:
       - name: "x402names", private: true
       - workspaces: ["apps/*", "packages/*"]
       - scripts: dev, db:generate, db:migrate (see RESEARCH.md Pattern 5 for exact commands)
       - No Turborepo for now (deferred per RESEARCH.md open question #1) -- just Bun workspaces

    2. Create root `tsconfig.json`:
       - strict: true, no implicit any, strict null checks (per CONTEXT.md decision)
       - target: ESNext, module: ESNext, moduleResolution: bundler
       - This is a base config -- apps extend it

    3. Create `.gitignore`:
       - node_modules, bun.lockb (optional -- some prefer to commit it), .env, .env.*
       - apps/api/data/ (SQLite database files)
       - *.db, *.db-wal, *.db-shm (SQLite WAL files)
       - dist/, .turbo/ (future-proofing)

    4. Create `apps/api/package.json`:
       - name: "@x402names/api"
       - dependencies: hono, drizzle-orm, envalid
       - devDependencies: drizzle-kit, @types/bun
       - scripts: dev ("bun --watch src/index.ts"), db:generate ("drizzle-kit generate"), db:migrate ("bun run src/db/migrate.ts")

    5. Create `apps/api/tsconfig.json`:
       - extends root tsconfig
       - compilerOptions: types ["bun-types"] (or @types/bun)
       - include: ["src/**/*.ts"]

    6. Create empty directories: `apps/api/src/`, `apps/api/data/`, `packages/`
       - Add `.gitkeep` in `packages/` to preserve the empty directory

    7. Run `bun install` from root to install all dependencies and generate lockfile.

    IMPORTANT: Do NOT add turbo as a dependency. Keep it simple with Bun workspaces only.

<task type="auto">
  <name>Task 2: Create environment config and database layer with migrations</name>
  <files>
    apps/api/src/config/env.ts
    apps/api/src/db/index.ts
    apps/api/src/db/schema.ts
    apps/api/src/db/migrate.ts
    apps/api/drizzle.config.ts
  </files>
  <action>
    Create the validated env config and full database layer.

    1. Create `apps/api/src/config/env.ts`:
       - Use envalid's cleanEnv to validate process.env
       - Required vars with defaults:
         - NODE_ENV: str, choices ['development', 'test', 'production']
         - PORT: port, default 3000
         - DATABASE_URL: str, default './data/app.db'
         - LOG_LEVEL: str, default 'info', choices ['debug', 'info', 'warn', 'error']
       - Export the validated `env` object
       - See RESEARCH.md Pattern 2 for exact implementation

    2. Create `apps/api/src/db/schema.ts`:
       - Define a `domains` table (Phase 1 foundation for future phases):
         - id: integer, primary key, autoIncrement
         - name: text, notNull, unique (e.g., "example.com")
         - tld: text, notNull (e.g., "com")
         - status: text, notNull, default 'pending' (pending | paid | registered | live | failed)
         - ownerWallet: text, notNull (wallet address that paid)
         - targetUrl: text (URL the domain points to)
         - paymentId: text, unique (x402 payment ID for idempotency)
         - registrarOrderId: text (external registrar reference)
         - createdAt: integer, timestamp mode, notNull, $defaultFn(() => new Date())
         - updatedAt: integer, timestamp mode, notNull, $defaultFn(() => new Date())
       - Also define a `system` table for key-value config:
         - id: integer, primary key, autoIncrement
         - key: text, notNull, unique
         - value: text, notNull
         - createdAt: integer, timestamp mode
         - updatedAt: integer, timestamp mode
       - Export all tables

    3. Create `apps/api/src/db/index.ts`:
       - Import Database from bun:sqlite
       - Import drizzle from drizzle-orm/bun-sqlite
       - Import env from config/env
       - Import * as schema from ./schema
       - Ensure data directory exists: use mkdir -p equivalent (Bun.write or fs)
         Actually use: `import { mkdirSync } from 'node:fs'` with `{ recursive: true }` on the directory portion of DATABASE_URL
       - Create Database instance with env.DATABASE_URL
       - Set pragmas (see RESEARCH.md Code Examples - Database Initialization):
         - PRAGMA journal_mode = WAL
         - PRAGMA busy_timeout = 5000
         - PRAGMA synchronous = NORMAL
         - PRAGMA cache_size = -64000 (64MB)
         - PRAGMA foreign_keys = ON
       - Export `db` (drizzle instance with schema) and `sqlite` (raw Database for cleanup)

    4. Create `apps/api/src/db/migrate.ts`:
       - Standalone script that runs migrations
       - Import Database from bun:sqlite, drizzle, migrate from drizzle-orm/bun-sqlite/migrator
       - Read DATABASE_URL from process.env with fallback to ./data/app.db
       - Create database, set WAL pragma
       - Run migrate with migrationsFolder pointing to ./drizzle (relative to apps/api/)
       - Log success and exit 0
       - See RESEARCH.md Pattern 3

    5. Create `apps/api/drizzle.config.ts`:
       - Use defineConfig from drizzle-kit
       - dialect: "sqlite"
       - schema: "./src/db/schema.ts"
       - out: "./drizzle"

    6. Generate the initial migration:
       - Run `cd apps/api && bun run drizzle-kit generate` (or equivalent from root)
       - Verify migration SQL files appear in apps/api/drizzle/

    7. Test the migration runner:
       - Run `bun run apps/api/src/db/migrate.ts`
       - Verify apps/api/data/app.db is created
       - Verify WAL mode: run a quick check that .db-wal file exists or query PRAGMA journal_mode

    IMPORTANT: The schema includes `domains` table even though it won't be used until Phase 4. This is intentional -- defining the core domain model now ensures migrations are additive (ALTER TABLE) rather than creating from scratch later. Claude should use discretion on column set -- the list above is a starting point, not exhaustive.
  </action>
  <verify>
    - `ls apps/api/drizzle/*.sql` shows at least one migration file
    - `bun run apps/api/src/db/migrate.ts` exits 0 with "Migrations complete" output
    - `ls apps/api/data/app.db` confirms database file was created
    - `bun -e "const db = new (require('bun:sqlite').Database)('apps/api/data/app.db'); console.log(db.query('PRAGMA journal_mode').get())"` shows WAL mode
  </verify>
  <done>
    Environment config validates at startup. SQLite database initializes with WAL mode and all production pragmas. Schema defines domains and system tables. Drizzle Kit generates migrations. Migration runner applies them to create the database.
  </done>
</task>
